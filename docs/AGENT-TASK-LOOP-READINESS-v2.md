### 已定位的失败

1. `mixed-02`的真实理解正确保留退款咨询和订单查询两个子请求，并选择query_order。但主request_type为inquiry，现有`validate_semantics`以`read_plan_requires_query`拒绝整个理解。SDK夹具没有覆盖这个真实的字段组合。需要针对任务模式明确混合只读计划的合法边界，保留普通咨询、身份和写入限制。
2. 捕获21次NextStep，9次携带了不适用的`knowledge_focus`，均被`knowledge_focus_requires_search`拒绝。例如ask_user/diagnostic_feedback同时带troubleshooting，prepare_refund同时带refund_policy。严格检查确实停止了非法步骤，但首轮排障和售后任务因此没有推进。不能删除约束来把失败改成通过；下一版需加强按动作区分的输出schema/提示，并用这些捕获输出增加反例。
3. 两条排障续答存在把“检查过”转述得更像“已确认正常”的倾向；不能只修结构后就认为语义质量已解决。
