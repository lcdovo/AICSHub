# 认证与权限

## 认证

- 登录接口为 `POST /api/v1/users/login`，请求体为 `{ "username": "...", "password": "..." }`。
- Access Token 使用 HS256 签名，默认 30 分钟过期；生产环境必须设置随机 `AUTH_SECRET_KEY`。
- Refresh Token 使用随机 JWT 标识并将 SHA-256 摘要写入 `refresh_tokens` 表，刷新时轮换旧令牌，退出登录时撤销令牌并递增用户 `token_version`。
- `role` 只从数据库读取，客户端传入的 `role` 参数不会改变权限。演示账号仅在 `AUTH_DEMO_ACCOUNTS_ENABLED=true` 的本地环境初始化。

## 权限矩阵

| 资源 | 普通用户 | 管理员 |
| --- | --- | --- |
| 自己的用户资料、会话、消息、反馈、工单 | 读写（按业务动作限制） | 读写 |
| 其他用户资源 | 拒绝（403） | 允许 |
| 用户列表、用户禁用、知识库管理 | 拒绝（403） | 允许 |
| 全量工单、转人工队列、客服人员、分析评测 | 拒绝（403） | 允许 |
| 健康检查、登录、刷新 Token | 公开 | 公开/登录后 |

## 限流与输入边界

登录和聊天默认分别限制为每 IP/用户每分钟 10 次和 60 次；消息长度、单文件大小和批量上传数量由环境变量控制。本地 profile 使用进程内限流，生产应接入 Redis 共享计数器。
