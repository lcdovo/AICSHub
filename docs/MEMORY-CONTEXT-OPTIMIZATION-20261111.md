## 有来源的结构化会话摘要

Run最终提交仍派发持久化summary Job，Worker在原事务/租约边界内处理。读取游标之后最多40条，达到20条才压缩，末尾10条仍由原始消息恢复。`Session.summary`继续使用Text列，保存`structured-excerpts-v2` JSON，`summary_policy`同步更新，无新增SQL迁移。

会话详情接口的`summary`字段仍是字符串，新摘要的字符串内容为上述JSON；读取该字段的外部客户端应识别内部policy，旧纯文本仍兼容。这次未新增摘要展示UI。

摘要按requests、conditions、suggested_steps、feedback、open_questions、other分类。每段保存原消息ID、角色和脱敏后的完整摘录；同一段可以同时属于诉求、条件和反馈。分类是有限规则，不是事实验证或一般语义理解。历史疑问不能证明问题仍未解决，助手建议不能证明用户已经执行。

单条不超过1000字符时保留整条；超长消息沿句末拆分，逗号、分号及转折不拆。无法容纳的完整长句明确计入`omitted_excerpts`，不截掉后半句的否定或条件。各类最多6条，保留最早两条和最近四条，普通闲聊不会直接挤掉条件类。持久摘要上限16000字符，超限继续按完整摘录淘汰并记录遗漏；因此不是无损存储，原始Message仍保留。

模型输入经`summary_context()`选择完整记录，各类轮流获得名额，跨类相同摘录去重，摘录序列化内容上限3000字符（外层字段另计）。它携带`trusted_as_current_evidence=false`和`grants_authorization=false`，按原消息ID说明先后与更正。当前任务状态继续来自现有`task_memory`/SQL任务恢复，不复制或推断另一套任务终态。

旧纯文本摘要按legacy_context兼容读取，不能还原历史上已经丢失的文字。首次新Job自然升级，不批量回填旧会话；独立新问题仍不携带历史摘要。SessionManager旧LLM摘要分支保留，本次优化的是Run主链路SQL后台摘要。

## 长期记忆允许空召回

用户/会话/删除隔离继续由原SQL查询负责。候选仍只包含其他会话的用户陈述，最近60条消息内粗排最多8条，默认最多返回5条。

- 向量召回仅接受有限且大于0、达到`USER_MEMORY_MIN_SIMILARITY`的余弦分数，默认0.65。
- 向量成功但全部不相关时返回空列表，不用关键词重新填满。
- Embedding故障时仍回退关键词，但要求至少一个有效双字或英文词匹配；常见问句先切开，避免“耳机如何/打印机如何”因“机如”误匹配。
- 无有效查询词、`USER_MEMORY_MAX_ITEMS=0`时不执行召回；工厂原先把0替换为5的问题一并修正。
- 0.65为保守可配置初值，不是实际Embedding已校准的语义门槛。模型/revision切换后需固定正负样本校准召回率及误召回率。

Settings、`.env.example`与Compose的API/Worker共享环境同步增加该配置。本地`.env`未修改。

## 隐式追问与主题切换

`build_request_context()`继续使用最多7条/每条600字符/合计2400字符的历史窗口。本轮消息只从尾部移除一次，不读旧工具结果或system消息。

在原有指代与补参规则外，增加近期用户话题关联、主体一致的待补参/待确认任务目标，以及排障任务确实等待反馈时的短反馈。例如包装损坏后“运费谁承担”、待排障时“红灯闪两次”可以获得背景；最近消息缺失时沿用现有带来源标记的任务目标提示。

显式换话题、新订单表达、与已知订单不同的当前订单号，以及常见产品明确切换时，阻止旧背景、默认订单和待办提示混入。产品边界只覆盖有限常见名称；未知产品、复杂跨主题表达仍需后续结构化理解/澄清，不保证任意中文理解。话题相关只影响背景选择，不能成为办理意图或当前事实。

回答策略版本更新到`answer-pipeline.v16-sourced-memory-context`，避免旧回答缓存/发布绑定跨本次上下文契约复用。
