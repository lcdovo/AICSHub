## 共享预算

`app/agent/context_budget.py`集中维护`context-budget.v1`。共同背景投影限12000 UTF-8字节；理解payload限16000、任务决策payload限32000、回答生成prompt限48000。UTF-8字节是保守输入规模代理，不是供应商精确token计数或实际费用。固定system/schema包装仍受原LLM网关、Judge的请求大小与费用门槛约束，本模块不修改这些门槛。

预算先完整预留当前问题、任务目标/参数/条件/事项和本轮观察/证据。超限按用户画像及召回、历史摘要、最早历史消息、最早任务笔记的次序，删除完整背景记录，记录`context_budget.omitted_items`。必要内容仍超限则抛出明确的预算异常，沿原调用方降级/停止路径处理，不截断证据的否定、条件或业务参数。层内原有候选条数与大小限制继续作为提取上限；共享预算负责组合后的总量，而非保证无损记忆。

回答画像不再独立以120字符切片拼接；历史及长期偏好通过同一个JSON数据投影注入。生成链路不重复发送同一历史为chat messages。理解语义校验只使用预算后实际发送的历史快照，不能用未发送的历史接受供应商参数。回答策略升为`answer-pipeline.v17-budgeted-memory-context`，旧缓存/发布绑定不跨版本复用。

## 一个摘要契约与持久入口

SQL的`Session.summary/summary_cursor/summary_version/summary_policy`是Run恢复的权威；Redis只是快照。Run和旧`ChatService.persist_result(commit=True)`都派发同一种持久summary Job，Worker统一使用`structured-excerpts-v2`。

`SessionManager.maybe_compress/_compress_context`保留非Run兼容能力，但只调用相同摘录契约，不再请求摘要模型，也不注入system摘要消息。旧私有`_generate_llm_summary`仅保留名称适配，不会调用模型。兼容路径不会在压缩后对摘要再次生成另一份摘要。没有SQL消息ID的旧内存内容只进入标为不可信的legacy背景，不伪造来源ID；无法保留的完整记录计遗漏。原始SQL消息不被删除或改写。

未批量改写存量纯文本摘要；SQL恢复可以覆盖旧Redis投影，历史已丢文字不能还原。

## 最小持久长期记忆

新增`user_memory_entries`及迁移`0014_user_memory_entries`。不是通用自动用户画像器：只接受完整消息形式的明确沟通偏好，当前范围为语言和详略。例如“以后请用简体中文回复我”“今后回答简洁一点”；“请忘记我的回复偏好”撤回这两类条目。含附加办理指令、引述或自由文本不匹配，不调用LLM提炼。订单现状、权限和确认不写成长期事实。

条目保存用户、偏好键、归一值、来源会话/消息、更新时间、180天到期时间和撤回时间。更新沿原消息ID排序；旧Run迟到或重放不能覆盖新更正/撤回，包括某个偏好尚未创建时先撤回产生的墓碑。MySQL写入锁定用户行以串行化跨会话首次创建，SQLite离线测试不代表MySQL生产并发验收。

REST与WebSocket均在共享ChatService的原Run提交事务中记录，事务失败不单独保存偏好；管理员代办不代表本人偏好。`USER_MEMORY_ENABLED=false`不采集。加载按当前用户、有效期、撤回状态、来源会话未删除、来源用户消息身份和原文语义重新核对；来源更改或会话软删除立即停止使用。旧偏好不再通过普通历史向量召回重新带回。

加载不依赖最近60条历史窗口；仅两个受限偏好槽位，无向量库/额外Embedding成本。历史普通陈述仍使用原有有门槛的跨会话召回。偏好只作背景、本轮明确要求优先，不是当前证据、系统指令或动作授权。服务端结构有效不等于真实模型一定遵循风格。

不自动扫描/回填旧消息，不执行生产DDL。部署需先在备份和常规迁移流程内运行`alembic upgrade head`，再更新API/Worker；本轮未执行。读取缺表时在savepoint内退化，保留普通历史功能；显式偏好写入要求迁移存在，失败时原事务不会假装成功。
