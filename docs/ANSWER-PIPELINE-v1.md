# 回答构建、审查与发布

2026-11-07。本片只做本地代码与T0离线验证，不新增真实供应商调用；不将本片替身结果计为M4/M5质量通过。

## 组件及边界

- `answer_builder.py`：选择本轮服务端通知、工具字段模板、缓存或模型草稿，不写assistant消息或发布token。
- `answer_review.py`：确定性检查先行，必要时调用独立LLM Judge，输出accepted/rejected/unknown及可修复错误码，不执行业务工具。
- `answer_publication.py`：核对审查输入绑定及最新知识发布快照，再渲染引用、检查最终文本、缓存及发布。没有审查结果不能发布原草稿。
- `answer_contracts.py`：构造生成与审查共用的本轮回答要求、策略指纹和输入指纹；不把理解结果/历史/业务槽位变成事实证据或操作权限。
- `nodes/response_node.py`：保留主图兼容入口、模型适配和模板助手，仅编排上述组件以及至多一次定向修复。

回答要求包含原消息、已有的有界上下文、条件、子请求、已知参数和缺失信息。Judge仍须对照原始问题，不能将上游理解遗漏当作用户没有提出要求。现有任务循环的diagnostic_feedback目标保留。

## 审查和失败分流

所有回复先检查敏感值、已识别的执行/金额/状态矛盾及引用。确定性错误不额外请求Judge。关键词重叠和长度保留为诊断信息，不作为完整性拒绝依据。

`needs_clarification`、`missing_slots`、smalltalk、handoff和rag_grounded标记均不能免除任意草稿的语义审查；无证据的模型回答同样审查。缓存命中也复审，不直接复用旧判决。

仅服务端固定流程通知与受限字段模板可走确定性通道。生产者通过`set_workflow_reply()`绑定当前用户/会话/消息/文本/工具记录/参数；文本或上下文改变则失效，新轮次不继承。禁止为模型补问、任意工具message/next_steps或异常详情添加该标记。退款确认只是服务端预览通知，不能授权执行。默认工具字段模板按本轮成功回执重建比对；投诉通知核对用户/会话后只渲染ID与状态，退款丢弃任意next_steps并按枚举重建类型/状态。其余携带自由指引的模板仍须Judge，条件/多子请求不按普通工具模板免审。固定通知仍运行公共确定性底线，不调用可替换的语义评分器。

| 审查情况 | 行为 |
| --- | --- |
| 正确完整回答 | 允许发布，满足其他约束才缓存 |
| partial/unknown证据，但回复正确说明限制或提出必要补问 | v2允许发布，不缓存 |
| 条件遗漏、范围扩大、否定改变、已知子问题遗漏或不必要补问 | 拒绝；模型草稿可定向修复一次，并完整复审 |
| Judge/确定性审查依赖失败、超时、非法输出或输入在等待中变化 | 审查unknown；不因该故障再次生成，发布审查降级说明 |
| 修复仍失败 | 终止该草稿；不自动跳转人工节点或创建业务请求 |

修复反馈通过异步ContextVar临时携带失败草稿、固定错误码及论断位置/摘要，不放入collected_info、Trace、消息或缓存。每次修复都回到原始证据，不把Judge结论当作新事实。

Judge v2契约修订为`judge.v2-candidate.2`，新增`unnecessary_clarification`，要求区分缺少资料与候选无效，检查已知问题遗漏、重复补问及补问中的事实承诺。引用ID/版本/原文存在只证明来源绑定，仍不能证明语义蕴含；模型漏报条件错误时，程序并不能自动发现所有问题。

保留现有v1/v2配置选择，不自动修改业务.env或启用尚未真实验收的v2。v1不具备v2的完整行为分类，不能把v2替身结果推广为v1或当前部署的效果。

## 发布和缓存

审查指纹绑定用户/会话/actor/Run/源消息、本轮要求、候选正文、完整知识证据与epoch、全部工具记录和策略指纹。等待Judge期间或发布前输入变化，原判决失效。发布前再次核对知识版本；失效/不可用时停止原事实回答，不附旧引用，不缓存。

v2引用只从判决实际使用的知识ID/版本中选择；v1保留原服务端引用方式。引用渲染器不得改变已审正文。最终发布底线仍检查全部公开文本，包括引用片段及安全终止说明。

缓存命名空间升级为`validated-v4:`并纳入回答策略指纹，隔离旧工作流免审策略结果。保留用户/上下文/模型/证据隔离，不缓存补问、拒答、partial、模型降级、未通过审查或有业务副作用的回答。
